# Protected worksheet rollout

The worksheet library keeps thumbnail URLs public. New printable files store a path such as `worksheets/<uuid>.pdf` in the existing `worksheets.file_url` column. The `worksheet-files` bucket is private. The application uses a server-only `SUPABASE_SERVICE_ROLE_KEY` to sign approved requests for 60 seconds.

In `npm run dev` without a signing key, signed-in users can preview the bundled originals from the local `worksheet-import/` folder through the same authenticated API. Production builds require private Storage.

For the daily-writing collection, place the five full-resolution WebP files in `worksheet-import/daily-writing/` and use `node --env-file=.env scripts/upload-bundled-worksheets.mjs --daily-writing --apply`. The repository contains only their thumbnails.

For the letter-group reader, place the 98 protected originals in `worksheet-import/letter-reading/`: main-page WebPs and story/overview PDFs under `he/` or `ar/`, and introduction, guide and activity-idea WebPs under `materials/<group>/`. Import with `node --env-file=.env scripts/upload-bundled-worksheets.mjs --letter-reading --apply` before deploying.

1. Apply `20261126000000_private_worksheet_files.sql` and configure the server environment. Keep the shared `site-media` bucket and its policies for other media.
2. Restore the bundled originals into a local `worksheet-import/` folder if necessary. Use the pre-change originals under `public/letter-groups/` from the previous release, keeping each path relative to that directory. Include full `stage-*-worksheet-*.webp` files and the three Arabic PNG originals and omit thumbnails. Run `node --env-file=.env scripts/upload-bundled-worksheets.mjs` to check the inventory, then append `--apply` to upload. The expected inventory is 153 originals. The script skips existing objects and never overwrites or deletes files.
3. Inventory all live worksheet rows, including hidden ones, and compare any public file paths against references in CMS content and thumbnails. The anonymous production read found one visible row pointing to a PDF under `/storage/v1/object/public/site-media/worksheets/`. Its URL returned `Object not found`. Locate the original PDF before updating this row. For an available legacy object in that folder on the configured project, copy it to the same path in `worksheet-files` with zero cache lifetime. The application can sign the private copy while the legacy reference remains in place. Verify the copy and update the specific row to store the object path. For an external URL or a legacy path outside `worksheets/`, upload a copy under `worksheets/` and update the row to that path. Preserve the original bytes and keep a mapping for rollback.
4. Deploy the application after the private copies are ready. Verify authenticated Preview and Print, the anonymous 401 response, and the absence of signed requests on library load. Check old static routes against the deployed version and purge old caches if applicable.
5. Any surviving `site-media` public URL remains reachable until its original object is withdrawn. Once all references and private copies have been verified and removal approved, retire only the specific public originals. The GitHub repository is public and past commits contain the bundled originals. Removing files from the application does not remove access through Git history, forks, or older deployment snapshots. Address those copies separately before treating the previously published originals as private.
